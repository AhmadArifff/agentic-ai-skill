# Workflow: Diagnosis & Perbaikan Eror 403 Forbidden (RBAC)

Gunakan alur kerja ini saat pengguna atau sistem mengalami eror `403 This action is unauthorized` saat membuka menu tertentu.

---

## Akar Masalah Umum 403:
1. Link menu di controller (`$this->parent_url`) tidak cocok dengan kolom `link` di tabel `menus`.
2. Role pengguna aktif (`auth()->user()->role_id`) belum memiliki baris izin di tabel `permissions` untuk `menu_id` terkait.
3. Cache permission di Redis/File masih menyimpan status lama sebelum permission di-insert.

---

## Langkah 1: Periksa Parent URL di Controller
Pastikan nilai `$this->parent_url` di constructor controller sama persis dengan yang ada di database:
```php
public function __construct(MyService $service)
{
    parent::__construct();
    $this->service = $service;
    $this->parent_url = 'nama-modul/index'; // Tanpa leading slash '/'
}
```

## Langkah 2: Periksa Tabel `menus` di Database
Jalankan pengecekan melalui Tinker atau SQL:
```sql
SELECT id, name, link, is_active FROM menus WHERE link = 'nama-modul/index';
```
* Jika kolom `is_active` bernilai `'n'`, ubah menjadi `'y'`.
* Catat nilai `id` menu tersebut (misal: ID = `72`).

## Langkah 3: Periksa Tabel `permissions`
Periksa apakah role pengguna (misal Super Admin `05581f52-1a25-4b51-97a1-e915c922ed39`) sudah terdaftar:
```sql
SELECT * FROM permissions WHERE menu_id = [ID] AND role_id = '[ROLE_ID]';
```
Jika belum ada, berikan akses penuh:
```sql
INSERT INTO `permissions` (`id`, `role_id`, `menu_id`, `create`, `read`, `update`, `delete`, `created_at`, `updated_at`)
VALUES (UUID(), '[ROLE_ID]', [ID], 1, 1, 1, 1, NOW(), NOW());
```

## Langkah 4: Bersihkan Cache Otorisasi
Sistem meng-cache permission berdasarkan role dan URL (`permission_{role_id}_{url}`). Bersihkan cache dengan:
```bash
php artisan optimize:clear
```
Minta pengguna me-refresh halaman browser.
